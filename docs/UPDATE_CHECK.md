# 手机端更新检查修复（v1.9.3）

## 修复原因

- GitHub REST API 匿名请求可能返回 403；不应把 API 限流当作软件版本。
- 手机、车机请求封装可能已把 JSON 转为对象，再次 JSON.parse 会失败。
- 旧流程用 0.0.0 代表获取失败，容易被误认为真实版本号。
- 部分 HTTP 200 返回的 CDN 内容也可能不符合清单格式，必须完整验证后再接受。

## 新链路

客户端读取本仓库 release-info 分支的公开 JSON 清单，依次尝试 Fastly、Gcore、jsDelivr 和 GitHub Raw 地址，每个地址设置 6 秒请求超时。清单校验失败或访问失败会继续尝试下一地址。所有地址均失败时明确显示获取失败，不会假报最新版，也不会创造 0.0.0。

默认只检查正式版；开启接收测试版后选择版本号更高的正式版/测试版。网络完全不可用时仍可能检查失败，无法承诺所有车机或运营商网络都可直连这些地址。

## 发布维护

- 新增 Publish Update Information 工作流，在打包发布成功后自动获取 GitHub 的公开 Release 信息并更新清单。
- GitHub API 仅在 Actions 的受权环境使用，不把任何令牌、个人凭据或私有同步地址写入客户端/清单。
- 初次运行会自动创建只含更新清单的 release-info 分支；可以在 Actions 手动运行此工作流刷新清单。
- 清单只包含已经发布且有安装包的版本，不把尚未完成的构建写为可更新版本。
- 本次不改同步协议、服务器或车机布局。

## 升级与验证

旧客户端中更新获取失败时，需要先从本仓库 Releases 手动下载安装本次修复版。请先备份歌单并覆盖安装，不需要清空应用数据。

自动测试覆盖对象/字符串响应、403、超时、无效 JSON、异常版本、安装包过滤、预览版选择、失败状态和自动发布清单生成。构建通过不代表所有网络/真机环境已经验收。
