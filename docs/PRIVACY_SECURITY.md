# 隐私与安全说明

更新日期：2026-10-11

## 日志保护

- 同步认证入口不输出连接码、认证请求对象或服务器完整地址。
- 应用日志在写入前尽力脱敏：网址、Bearer/Basic 凭据、常见令牌与密码字段、邮箱、手机号、用户主目录、私网 IPv4 地址，以及结构化日志里的账号与设备标识。
- 保留错误类型、调用名称和连接数量，便于排查问题。循环对象不会原样回退输出。
- 服务端连接与快照事件不直接记录用户名、设备名称或设备密钥标识。
- 脱敏不是匿名化保证；任意自然语言、第三方音源自身输出、系统原生日志或非标准字段可能不在规则内。分享日志前仍须人工检查。
- 本次升级不会删除旧日志。旧文件、备份与已经分享的日志不会被自动脱敏。

## 部署与数据

- 公网只能通过可信 HTTPS/WSS 反向代理访问。同步消息的压缩不等于加密，也不是端到端加密。
- 歌单、设置、自定义音源及设备认证信息保存在自己的数据目录。数据卷与备份都应限制访问，不能放入公开仓库或公开下载目录。
- 音源脚本可能包含私人服务地址或访问令牌，仅向自己信任的设备同步。
- 不提交真实部署配置、环境文件、签名密钥或容器日志。本仓库增加了对应忽略规则，但已跟踪的文件不受忽略规则保护。
- 示例与上游公开测试密钥不是生产凭据；Android 测试签名不适合作为正式发布的身份保证。

## 提交身份与历史

本轮维护提交使用 GitHub 的 noreply 身份。该设置仅作用于当前工作副本，不修改整台电脑的全局 Git 配置，也不会改写旧提交。

旧提交中的邮箱、旧发布包和旧日志仍可能保留原信息。重写历史会改变提交编号并影响分支和标签，必须单独确认后再执行；即使重写也无法撤回他人已经克隆或缓存的副本。

## 回归检查

运行 `npm run test:privacy` 检查脱敏规则、日志接入以及敏感文件忽略规则。默认分支与拉取请求会自动运行，发布流程也会在打包前检查。它用于防止已知问题回归，不替代完整安全审计。
